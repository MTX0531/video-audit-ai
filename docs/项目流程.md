# 项目流程（视频 AI 稽核系统）

## 一、整体流程

```
门店摄像头(FTP 拉取)
   │  店内局域网
   ▼
store_capture.py ──FTP拉取·切片(≤30min/段)·编码探测·转码兜底──▶ 上传 Notion 视频台账库
   │                                                           （建「待处理」页）
   ▼
自动化轮询（每30min）
process_pending.py ──下载视频──▶ 本地 AI 稽核管线
   │                              ├─ count_people.py   YOLO 人数统计（ByteTrack 跟踪）
   │                              ├─ describe_qwen.py  VLM 内容描述（在场/出入/活动）
   │                              └─ build_report.py   HTML 稽核报告
   ▼
报告回写 Notion 报告库（新建关联报告页，不改原视频页）
```

## 二、角色划分（门店 / 总部）

| 角色 | 职责 | 依赖 |
|---|---|---|
| **门店侧** | FTP 拉取 + 切片 + 上传 Notion | ffmpeg + Python，**不跑 AI**（无 GPU 要求） |
| **总部侧** | 下载 → CV 人数统计 → VLM 描述 → 报告生成 | Apple Silicon + 模型权重 |

> 设计约束：门店工作人员不手动下载视频，视频进入管线的唯一入口是门店侧 FTP 拉取。

## 三、关键子流程

### 3.1 FTP 拉取与切片（store_capture.py）
1. 按 `cameras.json` 的 `ftp_*` 配置，周期性连接录像机/监控平台 FTP，拉取新增录像文件（断线自动重连）
2. 拉取完成后 ffmpeg `-c copy` 免转码切片（默认 30 分钟/段），无 ffmpeg 时整文件作为单片段上传
3. 上传前 `ffprobe` 探测容器+编码：非 `mp4+H.264` 自动转码
4. 上传成功后片段移入 `uploaded/`，本地 `.capture_state.json` 记录已传片段（重启不重传）
5. FTP 拉取幂等：远程文件切完后源文件移入 `raw/processed/`，不会重复拉取/切片

### 3.2 AI 稽核（process_pending.py）
1. 扫描台账库「待处理」视频（以报告库关联差集判定）
2. 下载视频 → `video_can_decode()` 验证可解码（防格式异常）
3. 跑 CV 人数统计（可被 `video_params.json` 按页 id 覆盖参数：ROI / min_area / no_track）
4. 跑 VLM 内容描述
5. 生成 HTML 报告 → 上传 Notion → 报告库新建关联页

### 3.3 格式兜底（双保险）
- **入口**：门店侧探测并转码（需门店机装 ffmpeg）
- **出口**：总部侧解不出首帧 → 建「⚠格式异常」记录页 → 不再无限重试 → 人工排查

## 四、数据流与状态

| 阶段 | 台账库状态 | 说明 |
|---|---|---|
| FTP 拉取上传 | 待处理 | 视频本体 + 店名/摄像头/起止元数据 |
| 稽核中 | 处理中 | 下载并开始 CV/VLM |
| 完成 | 已生成 | 报告库出现关联报告页（视频页不回改，因 integration 仅 Read+Insert） |

## 五、容量与边界

- 单文件上限 5GB（Notion 限制）；视频本体方案适合 ≤2~3 店试点
- 每店 30 分钟一段 ≈ 约 31MB（720p 低码率录像文件）；一天 ≈ 1.7GB
- 超出试点规模时：视频改存对象存储（COS/OSS/MinIO），Notion 只存台账与报告
